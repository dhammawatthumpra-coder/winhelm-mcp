## Phase 1 implementation

Files changed:

- `src/runtime/internal-port.ts`
- `src/gateway/server.ts`
- `src/index.ts`
- `test/unit/dynamic-internal-port-v1_4_1.test.ts`

Implemented behavior:

1. Core accepts `--port auto` or `PORT=auto`.
2. Existing precedence remains CLI > environment > legacy default.
3. Existing absent-port behavior remains fixed `8788`; existing installs are not silently migrated.
4. Empty `PORT=""` preserves v1.4.0 fallback-to-8788 behavior.
5. Numeric fixed mode accepts only 1..65535.
6. Auto mode is loopback-only at both resolver and bind-primitive layers.
7. Sticky-auto preference is stored at `~/.winhelm/runtime/preferences/core.json`.
8. Sticky state is only a validated preference hint; malformed/missing state is ignored.
9. The allocator never performs check-port-then-bind.
10. Auto first attempts the sticky preferred port by the real bind operation.
11. Only `EADDRINUSE` on the sticky preferred bind triggers fallback.
12. Fallback binds port `0` directly and accepts the OS-selected bound port.
13. Non-collision bind errors remain fatal.
14. Fixed-port collision remains fail-closed and never falls back.
15. The actual bound listener port continues to feed `ConfigManager.setRuntimeEffectivePort`.
16. Existing `createServer({port,host,...})` callers remain compatible.
17. Public HTTPS 443, public hostname, MCP/OAuth identity, issuer, redirects, scopes, and public routing were not modified.
