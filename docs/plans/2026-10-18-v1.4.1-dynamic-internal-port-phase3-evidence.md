## R7 Core discovery contract

`resolveR7CoreBackend(...)` has two explicit modes.

Fixed mode:

- requires loopback;
- uses the configured numeric Core endpoint directly;
- does not consult the runtime registry;
- therefore preserves the legacy fixed Core path.

Auto mode:

- requires trusted expected Core executable and entrypoint paths;
- reads the Core registry only as a hint;
- calls the Phase-2 verified resolver;
- requires current PID + process creation time + executable + command-line entrypoint + listener-owner PID + live health generation proof;
- rejects the endpoint if any proof is absent or mismatched;
- refuses R7 startup before listener bind if no verified Core endpoint exists.

No mutable timestamp or host/port JSON is independently trusted.

## R7 listener and sticky-auto contract

R7 listener selection reuses the race-safe Phase-1 bind primitive.

For auto mode:

1. optional `r7` sticky preference is read only as a hint;
2. a preferred port is acquired only through the real listener bind;
3. `EADDRINUSE` alone permits fallback to an OS-selected `:0` bind;
4. unrelated bind errors remain fatal;
5. the actual bound port is read from the listener;
6. R7 runtime identity is verified;
7. `r7.json` is atomically published;
8. sticky preference is written only after verified readiness.

The sticky preference is not authority. A sticky-persistence failure after verified publication is non-fatal and may only emit a sanitized warning.

Fixed numeric listener selection remains supported by the same binder. The existing qualified fixed `127.0.0.1:64239` R7 reference lane was deliberately left unchanged rather than mutated for this phase.

## R7 health identity

The shared endpoint verifier now has an additive optional `expectedHealthServer`.

Default behavior remains:

`winhelm-mcp`

so existing Core verification is unchanged.

R7 publishes health identity as:

```json
{
  "status": "ok",
  "server": "winhelm-r7",
  "runtime": {
    "role": "r7",
    "generation": "<current-generation>",
    "pid": "<current-pid>"
  }
}
```

The R7 health route is visible only to a loopback probe presenting:

`x-winhelm-runtime-generation: <current-generation>`

An ordinary request to R7 `/health` receives a hidden 404, while normal R7 request routing remains delegated to the reviewed R7 server.

This generation header is an identity-binding input for the local verifier, not a public authentication mechanism.
